# 픽셀 동물 스타일 가이드

macOS 화면에 항상 떠 있는 캐릭터 앱에서 쓸 동물 스프라이트의 제작 규칙입니다. 수치의 근거는 레퍼런스 분석 보고서(`report.html`, 로컬 전용)에 있습니다.

## 1. 해상도와 크기

- 스프라이트는 원본 해상도(1칸 = 1px)로 그리고, 화면에서는 **실제 화면 픽셀 기준으로 정수배**가 되도록 확대합니다.
- 앱의 기본 배율은 **1칸 = 2.5pt**입니다. Retina 화면에서는 1pt가 기기 픽셀 2개라서, 1칸이 정확히 5×5 기기 픽셀이 됩니다. 사용자가 고를 수 있는 배율은 1, 2, 2.5, 3배입니다.
- Retina가 아닌 화면(기기 배율 1x)에서는 2.5배가 픽셀마다 2px과 3px로 번갈아 그려집니다. 이런 화면에서는 가까운 정수 배율(2배 또는 3배)로 바꿔 그립니다(`NSScreen.backingScaleFactor`로 확인).
- 모든 동물에 같은 배율을 씁니다. 동물의 실제 크기 차이는 픽셀 수로 표현합니다.

| 동물 | 몸길이 (꼬리 포함) | 프레임 크기 |
|---|---|---|
| 햄스터 | 14px (몸 13×10, 꼬리 1px) | 26×28 (지름 26px 쳇바퀴와 톱밥 더미를 위한 여백 포함) |
| 황제펭귄 | 키 19px (몸 약 12×16, 부리와 발 포함 13×19). 새끼 8×10 | 38×32 (썰매의 눈가루, 떨어지는 물고기, 새끼를 위한 여백 포함) |
| 웰시코기 | 몸 약 28×20px (머리와 귀를 크게, 다리 3px) | 44×26 (구르기, 테니스공을 위한 여백 포함) |
| 닥스훈트 | 몸 약 33×17px (머리를 크게, 다리 3px) | 50×28 (굴 앞 흙더미와 뒤로 날아가는 흙을 위한 여백 포함) |
| 시바견 | 몸 약 26×21px (실제 비율: 길이 ≈ 높이, 다리 7px) | 38×24 (달리기에서 앞뒤로 뻗는 다리와 목줄을 위한 여백 포함) |
| 흑갈색 시바 | 시바견과 같음 (색만 다름) | 38×24 |
| 래브라도 | 몸 약 36×30px (대형견: 시바의 약 1.4배, 다리 10px, 3px 굵기) | 54×34 (달리기에서 앞뒤로 뻗는 다리를 위한 여백 포함) |
| 고양이 | 20~24px | 미정 |
| 여우 | 약 34px | 40×42 (높은 점프와 기지개를 위한 여백 포함) |
| 큰 개 | 45~50px | 미정 |

- 프레임 크기는 한 동물의 모든 프레임에서 같습니다. 가장 큰 자세(점프, 기지개)가 들어가도록 정합니다.
- 기준점(`anchor`)은 발바닥 선의 가운데입니다. 앱은 이 점을 화면의 바닥선에 맞춰 그립니다.

## 2. 형태

- 오른쪽을 보는 측면 뷰만 그립니다. 왼쪽 방향은 앱에서 좌우 반전합니다.
- 발바닥 선은 프레임의 맨 아래 줄입니다. 점프처럼 발이 뜨는 프레임만 예외입니다.
- 네 다리 모두 2px 두께로 그립니다. 먼 다리는 한 단계 어두운 색으로 칠하고, 짝이 되는 가까운 다리보다 조금 뒤에 둡니다. 그래서 몸 뒤쪽부터 먼 뒷다리, 가까운 뒷다리, 먼 앞다리, 가까운 앞다리 순서로 놓입니다. 두께를 다르게 하면 달릴 때 굵은 다리와 가는 다리가 번갈아 보여 어색해집니다.
- 움직이는 다리는 **뼈 길이를 고정한 2관절 IK**로 그립니다. 프레임마다 발끝 위치만 정하고 무릎은 뼈 길이로 계산합니다. 앞다리의 가운데 관절은 앞으로, 뒷다리는 뒤로만 접힙니다. 좌표를 직접 찍거나 평균 내면 다리가 프레임마다 늘었다 줄었다 해서 젤리처럼 보입니다.
- 몸통, 목, 다리의 접합부가 가늘어지거나 끊기지 않게 합니다. 흰 털과 무늬의 경계는 직각으로 꺾지 않고 곡선으로 잇습니다.
- 눈은 코와 같은 색이지만 팔레트 문자를 따로(`o`) 둡니다. 깜빡임이 이 문자만 바꾸기 때문입니다.
- 여우의 발끝은 흰색입니다(가까운 발 `p`, 먼 발 `q`). 다리를 그릴 때 끝점을 발 색으로 칠하므로, 긁거나 점프할 때처럼 발이 위를 향해도 정확히 발끝만 칠해집니다. 흰 발을 없애려면 `p`, `q`의 색을 다리 색과 같게 바꾸면 됩니다.
- 눈은 1px, 코는 1~2px입니다. 종의 특징은 귀 모양, 꼬리, 무늬, 털 색으로 표현합니다.
- 햄스터의 눈은 1×2px 세로 눈입니다(위 `o`, 아래 `v`). 깜빡일 때 위 칸은 털 색, 아래 칸은 어두운 선이 됩니다(`blink.swap`).
- 머리가 작으면(가로 8px 이하, 햄스터) 머리 방향은 코드로 회전하지 않고 손으로 그립니다. 회전하면 줄무늬, 귀, 눈이 뒤섞입니다.
- 몸을 부풀리거나 늘일 때는 한 행이나 한 열을 통째로 반복합니다(숨쉬기, 달리기, 기지개). 일부 열만 움직이면 둥근 윤곽에 혹이 생깁니다. 귀가 있는 열은 반복하지 않습니다.

## 3. 색

- 동물 한 마리당 5~10색을 씁니다.
  - 주된 털 색: 3~4단계 (밝음, 기본, 어두움, 가장 어두움)
  - 두 번째 털 색 (크림, 흰 털 등): 2단계
  - 다리나 발: 필요하면 1~2색
  - 눈과 코: 1색
- 한 털 색 안에서는 색조를 거의 고정하고, 명도(HSV의 V)만 한 단계에 약 6~11%p씩 바꿉니다.
- 위쪽(등, 머리 윗면)은 밝게, 아래쪽(배, 다리 안쪽)과 먼 쪽은 어둡게 칠합니다.
- 안티에일리어싱과 디더링을 쓰지 않습니다.

## 4. 테두리

- 스프라이트 자체에는 외곽선을 그리지 않습니다.
- 앱이 그릴 때 **흰색 1px 테두리를 4방향(상하좌우)으로** 생성합니다. 대각선 모서리는 채우지 않습니다.
- 밝은 배경에서는 흰 테두리가 보이지 않습니다. 그래서 몸 아래쪽 가장자리를 어두운 단계로 칠하는 3번 규칙이 윤곽 역할을 합니다.
- 반사 그림자는 쓰지 않습니다.
- 몸 가장자리에 흰색에 가까운 색을 쓰면 흰 테두리와 합쳐져 그 부위가 커 보입니다. 햄스터의 흰 방울 꼬리는 한 단계 어둡게(`#cbbfb2`) 칠합니다.
- 효과 표시처럼 작은 글자 모양의 픽셀(잠결의 `zzz`)은 테두리를 두르지 않습니다. 흰 테두리가 1px 틈을 메워 글자가 뭉개지기 때문입니다. 날아가는 톱밥 조각이나 씨앗 부스러기처럼 작은 효과 픽셀도 마찬가지입니다(테두리를 두르면 별처럼 보임). 이런 색은 `"outline": {"skip": [...]}`에 적습니다.

## 5. 애니메이션

- 모든 동작은 50ms 틱의 정수배로 재생합니다. 느긋한 동작(IDLE, 걷기)은 프레임마다 2틱 이상 머물러 원본처럼 10fps로 보이고, 움직임이 큰 동작(달리기, 점프의 공중 구간)은 1틱마다 바꿔 20fps로 보입니다.
- 부드러움은 fps가 아니라 사이 그림의 수에서 나옵니다. 같은 그림을 더 자주 보여줘도 달라지지 않습니다. 움직임이 큰 구간은 키 포즈 사이에 중간 프레임을 넣고, 자세를 바꾸는 전환은 한 단계에 2~3틱씩 여러 단계로 나눕니다.
- 반복 동작(`loop: true`)과 한 번 재생하는 전환 동작(`loop: false`)을 구분합니다. 전환 동작은 마지막 프레임에서 멈춥니다.
- 이동하는 동작은 `moveX`(틱마다 이동하는 픽셀 수)를 적어서, 발이 바닥에서 미끄러지지 않게 합니다.
- 같은 프레임을 다시 써도 됩니다. 순서 배열에 같은 프레임 이름을 한 번 더 넣습니다.
- 도입부 뒤에 반복하는 동작(웅크려 잠들기, 앉아서 긁기)은 `loopFrom`으로 반복을 시작할 단계를 적습니다. 이런 동작은 다음 이벤트가 올 때까지 계속됩니다.
- 점프처럼 특정 단계에서만 앞으로 나아가는 동작은 그 단계에 이동 픽셀 수를 적습니다: `["pounce_2", 1, 3]`.
- 가만히 있을 때 가끔 섞는 동작은 `idleVariants`에 적습니다(여우: 핥기, 긁기, 귀 기울이기. 햄스터: 킁킁, 세수, 일어서서 두리번).

### 동작 사이를 자연스럽게 잇는 규칙

- **머무는 시간(`hold`)**: 한 번 재생하는 동작은 끝난 뒤 마지막 자세에 잠시 머뭅니다. 기본은 0.3초이고, 앉기 2.5초, 엎드리기 3초처럼 동작마다 정합니다.
- **자세(`pose`)**: 동작마다 시작 자세와 끝 자세를 적습니다(`stand`, `sit`, `lie`, `curl`, `bow`, `running`). 적지 않으면 서서 시작하고 서서 끝납니다.
- **전환표(`transitions`)**: 자세 사이를 잇는 전환 동작입니다. 다음 동작의 시작 자세가 지금 끝 자세와 다르면, 앱이 이 표에서 경로를 찾아 전환 동작을 먼저 재생합니다. 예를 들어 잠든 상태에서 기지개를 켜면 `uncurl`(몸 풀기) → `lie_up`(일어서기) → `stretch` 순서가 됩니다. 엎드린 뒤 바로 웅크려 잠드는 경우처럼 자세가 이미 맞으면 전환 없이 이어집니다.
- **도입부**: 자세를 바꿔야 하는 반복 동작은 앞에 들어가는 프레임을 두고 `loopFrom`으로 반복 구간을 정합니다(땅 파기, 긁기).
- **끼어들기**: 새 이벤트가 오면, 한 번 재생하는 동작(일어서기, 점프 도중)은 끝까지 마친 뒤 넘어갑니다. 반복 동작(자기, 땅 파기, 걷기)은 바로 멈추고 전환 동작을 거칩니다.
- 빌드는 전환표의 각 경로가 실제로 두 자세를 잇는지, 모든 자세에서 선 자세로 돌아갈 길이 있는지 검사합니다.

| 시바견 | `mikaeri` | 미카에리: 멈춰 서서 어깨 너머로 고개를 돌려 화면을 돌아봄 |

| 시바견 | `shake` | 눈을 질끈 감고 옆모습 그대로 머리를 비틀듯 흔들고, 귀는 바깥으로 펄럭이고, 다리를 넓게 벌려 버팀. 머리는 코를 축으로 구르고, 몸통이 반 박자 늦게 반대로 구르며 물방울이 튐. 머리 → 몸 전체 → 엉덩이와 꼬리 순서로 번졌다 잦아듦 |
| 래브라도 | `wag` | 굵은 수달 꼬리가 위 → 옆 → 뒤로 크고 빠르게 쓸리고 귀가 펄럭임. 몸과 다리는 제자리 |
| 래브라도 | `show` | 노란 오리 장난감을 위턱과 아래턱 사이에 물고, 고개를 든 채 앞발을 번갈아 높이 들며 뽐냄. 오리를 두 번 삑삑 누름 |

## 6. 마우스 추적

IDLE 상태에서는 얼굴이 마우스 커서를 따라갑니다. 측면 뷰에서 전방향을 표현하기 위해 두 가지를 조합합니다.

- **좌우**: 커서가 몸 가운데보다 `turnMargin`(4px) 이상 뒤로 가면 `turn` 동작으로 돌아섭니다. 여우가 화면 쪽으로 몸을 돌려 3/4 정면과 정면 자세를 거친 뒤, `flipAt` 단계부터 좌우 반전된 3/4 정면을 거쳐 반대 방향을 봅니다. 기존 측면 그림을 좁히거나 뒤집는 방식은 세로축을 중심으로 그림만 돌아가는 것처럼 보여서 쓰지 않습니다.
- **눈 깜빡임**: IDLE 중 2.5~6초마다 0.1초 동안 눈(`o`)을 털 색(`d`)으로 바꿉니다. 네 번에 한 번쯤은 두 번 연달아 깜빡입니다. 머리가 어느 방향을 보든 적용됩니다.
- **상하**: 눈에서 커서까지의 각도(바라보는 쪽 기준, 위 90°, 아래 −90°)로 머리 방향 5단계 중 하나를 고릅니다.

| 방향 | 각도 | 표현 |
|---|---|---|
| `up` | 60° 이상 | 머리를 55° 돌려 올려다봄 |
| `up_fwd` | 20° ~ 60° | 머리를 25° 들어 올림 |
| `fwd` | −20° ~ 20° | 기본 자세 |
| `down_fwd` | −60° ~ −20° | 머리를 22° 숙임 |
| `down` | −60° 미만 | 머리를 30° 숙이고 목을 3px 낮춤 |

- 머리는 모두 같은 방식으로 돌립니다. 8배로 키운 상태에서 회전하고, 8×8 칸마다 가장 많은 색으로 다시 줄입니다(RotSprite 방식). 그 뒤 눈과 코를 원래 위치에서 회전한 자리에 1px씩 다시 찍고, 이웃이 없는 외톨이 픽셀은 지웁니다. 귀는 가는 삼각형이라 이 방식으로 돌리면 끝이 깎이므로, 회전에서 빼고 모양 그대로 회전한 머리 위 제자리에 옮겨 붙입니다.
- 아래를 볼 때는 머리를 크게 꺾지 않고 목을 낮춥니다. 45° 넘게 꺾으면 이 해상도에서는 귀와 눈, 코가 뭉개져 얼굴로 읽히지 않습니다. 세로로 비트는 방식(기울이기)은 주둥이가 늘어나서 쓰지 않습니다.

- 커서가 머리에서 `deadZone`(6px) 안에 있으면 방향을 바꾸지 않아서 떨림을 막습니다.
- 방향마다 IDLE의 모든 프레임에 대응하는 머리 프레임이 있어서, 숨쉬기와 꼬리 흔들기는 그대로 유지됩니다.
- macOS 앱에서는 `NSEvent.mouseLocation`을 주기적으로 읽으면 되고, 권한이 필요 없습니다.

## 7. 데이터 형식

동물 하나가 `sprites/<name>.json` 파일 하나입니다. `node tools/build.mjs`가 검증한 뒤 `dist/`에 뷰어용 번들과 PNG 시트를 생성합니다.

```jsonc
{
  "name": "fox",
  "size": [34, 22],                 // 프레임 크기
  "anchor": [17, 21],               // 발바닥 선 가운데
  "palette": { "b": {"hex": "#dc7b3a", "role": "털 기본"}, ... },   // "."은 투명
  "frames": { "idle_0": ["....", ...], ... },                      // 한 줄 = 픽셀 한 행
  "animations": {
    "idle": {"loop": true, "seq": [["idle_0", 4], ...]},           // [프레임, 틱]
    "sit": {"pose": ["stand", "sit"], "loop": false, "hold": 25, "seq": [...]},
    "pounce": {"loop": false, "seq": [..., ["pounce_2", 1, 3]]},   // [프레임, 틱, 이동 px]
    "curl_sleep": {"loop": true, "loopFrom": 2, "seq": [...]}      // 2단계부터 반복
  },
  "transitions": { "sit": {"stand": ["sit_up"]}, "curl": {"lie": ["uncurl"]}, ... },
  "look": {                          // IDLE에서 마우스 추적
    "animations": ["idle"], "headCenter": [31, 20],
    "sectors": [{"dir": "up", "min": 60}, ...], "deadZone": 6, "turnMargin": 4,
    "frames": {"up": {"idle_0": "idle_0_up", ...}, ...}           // 방향별 프레임 교체표
  },
  "planned": [],                     // 아직 그리지 않은 동작
  "inProgress": true,                // 지금 작업 중인 동물. 뷰어가 이 동물을 먼저 보여 줌 (주소에 ?animal=<name>을 붙이면 그 동물)
  "idleVariants": ["lick", "itch", "listen"],
  "reactions": { "alert": ["listen", "pounce"], ... }              // 반응 → 재생할 동작 순서
}
```

- 프레임 이름은 `<동작>_<번호>` 형식입니다. 동작에 속하지 않는 기준 자세는 `stand`처럼 따로 둡니다.
- 팔레트 문자는 한 글자이고, 역할(`role`)을 함께 적습니다. 팔레트만 바꿔 털 색 변형을 만들 수 있습니다.

## 8. OS 이벤트 연결

이벤트와 동작은 두 단계로 연결합니다.

1. `events.json`: OS 이벤트를 동물과 무관한 **반응**(alert, curious, greet, wake, sleepy, celebrate, busy, wander)으로 바꿉니다.
2. `sprites/<name>.json`의 `reactions`: 각 동물이 반응마다 재생할 동작 순서를 정합니다.

그래서 동물을 추가해도 이벤트 쪽은 바꿀 필요가 없습니다. 반대로 이벤트를 추가해도 기존 반응에 연결하면 동물 데이터는 그대로 둡니다. 아직 그리지 않은 동작은 건너뛰고, 재생할 동작이 하나도 없으면 현재 동작을 유지합니다.

### macOS에서 받을 수 있는 이벤트

`events.json`의 이벤트는 출처(`source`)가 세 가지입니다.

- `system`: macOS 공개 API로 받습니다. 모두 권한이 필요 없습니다.
- `app`: 앱 안에서 생깁니다. 포모도로 타이머의 종료와 휴식 시작, 캐릭터 클릭입니다. "알림" 반응은 우선 앱의 타이머에만 연결합니다.
- `external`: 다른 프로그램이 앱에 보냅니다. 앱은 `pixipet://event/<이벤트 id>` URL 스킴을 등록하고, 이 URL을 받으면 해당 이벤트를 발생시킵니다.

### Claude 작업 알림 연결

Claude Code의 훅(hook)으로 `external` 이벤트를 보냅니다. `~/.claude/settings.json`에 다음을 추가합니다. `open -g`는 앱을 앞으로 가져오지 않고 URL만 전달합니다.

```json
{
  "hooks": {
    "Stop": [{"hooks": [{"type": "command", "command": "open -g 'pixipet://event/claude.taskDone'"}]}],
    "Notification": [{"hooks": [{"type": "command", "command": "open -g 'pixipet://event/claude.needsInput'"}]}]
  }
}
```

- `Stop`은 Claude가 응답을 마칠 때마다 실행됩니다. 긴 작업만 알리고 싶다면, 앱에서 같은 이벤트가 짧은 간격으로 반복될 때 무시하도록(`cooldownSec`) 처리합니다.
- `Notification`은 Claude가 권한 승인이나 입력을 기다릴 때 실행됩니다.
- 앱이 아직 없으므로 이 설정은 앱을 만든 뒤에 적용합니다. 그 전까지는 뷰어의 이벤트 시뮬레이터로 동작을 확인합니다.

받을 수 없거나 제약이 큰 이벤트도 있습니다.

- **다른 앱이 보낸 알림**: 다른 앱의 알림을 가로채는 공개 API가 없습니다. 대신 앱의 타이머와, URL 스킴으로 이벤트를 보내 주는 도구(Claude Code 훅 등)를 씁니다.
- **집중 모드 상태**: 공개 API로는 상태를 자세히 알 수 없습니다.
- **키보드 입력**: 전역 키 입력을 감지하려면 손쉬운 사용 또는 입력 모니터링 권한이 필요합니다. 입력이 있었는지만 알면 되는 경우는 `user.idle`처럼 권한 없이 처리합니다.
